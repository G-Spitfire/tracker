## Фактическое исходное состояние

Создание/переименование сотрудников, помещений и названий уже существовали, рабочий график также. Полных редакторов групп и произвольных типов не было. Прежняя архивация сотрудников/помещений предлагала переназначать будущие записи, архивация названий могла отменять/убирать будущие занятия. Запрет окончательного удаления был отдельным только для сотрудников. Стартовые seed-списки и фиксированная тройка типов могли восстанавливать удалённые объекты и терять произвольные типы.

## Что сделано

- Единый компактный редактор пяти справочников в существующем стиле: создание, правка и удаление. Для сотрудника сохранены должность и рабочий график; для типов — цвет; для названий — выбор типа.
- Все операции идут через канонический документ и replace: одна запись, проверка целостности/права вкладки. Отмена справочников не введена. Успешная правка сбрасывает старую отмену расписания согласно этапу 2, отказ записи её не сбрасывает.
- Использование ищется во всех сохранённых записях, включая прошлые даты и скрытые отменённые записи. Совместное событие считается одной записью. Удаление используемого объекта запрещено с количеством связей. Тип блокируется также зависимыми названиями; сотрудник — сохранёнными отсутствиями. Назначения не снимаются, связанные записи не удаляются.
- Неиспользуемые объекты удаляются. У удалённого помещения очищается только настройка кабинета по умолчанию; у сотрудника — его служебные настройки; после удаления неиспользуемой группы настройки кабинетов перенумеровываются по сохранённым ID групп.
- Переименование сохраняет ID и меняет отображение всех дат без истории названий. Старая разбивка ФИО не перекрывает новое имя. Имена проверяются на пустоту, служебное значение и дубли без учёта регистра/лишних пробелов/Unicode-совместимых символов.
- Новые типы и их цвета сохраняются при последующих правках расписания и reload. Изменение типа названия обновляет связанные записи целиком. Совместное мероприятие может выбрать название из справочника, сохраняя единую запись; свободное название остаётся доступно.
- Доска учитывает фактическое число групп. Стартовые списки и прежние миграции не воскрешают удалённые объекты. Прежние архивные объекты не удалены, отображаются в общем списке с пояснением и отдельным восстановлением без изменения расписания. Опасные обработчики архивации/переназначения убраны.
- Схема и полная резервная копия версии 1 сохранены. Архитектура уточнена в ARCHITECTURE.md.

## Ограничения

- Сохранённые отсутствия — дополнительные связи сотрудника: перед удалением такого сотрудника нужно явно удалить соответствующие отметки. Существующие данные не удаляются автоматически.
- Старая архивная запись остаётся архивной до явного восстановления, даже если не используется. Новая архивация не предлагается.
- Индивидуальные цвета названий из старой версии сохраняют приоритет над цветом типа; они не стираются автоматически.
- Отдельной истории/отмены справочников нет. Ограничения localStorage и режим единственного писателя из этапа 2 сохранены.
