Исходная версия: `d41099498c6faae9748a46ea91cd7aadd90313fb` (17.11.2026).
Неизменённая контрольная ветка: `aspect/baseline-stage1-20261117`.
Источник продуктовых решений — PROJECT.md. Этот документ описывает реализацию, не изменяет требования.

## Каноническое хранение

`model.js` хранит один JSON-документ в `aspect_document_v1`:

- `schemaVersion: 1` — версия схемы, неизвестная версия отклоняется;
- `catalogs.groups` — `{id, name}`; порядок текущих шести групп сохранён;
- `catalogs.staff`, `catalogs.rooms` — `{id, name, archived}`;
- `catalogs.types` — `{id, name, color}`; текущие subject/routine/event;
- `catalogs.activities` — `{id, name, typeId, archived, color}`;
- `days[YYYY-MM-DD].entries` — единый массив уроков, режимных записей и мероприятий;
- `days[date].absences` — причины отсутствия по ID сотрудника;
- `settings` — настройки существующего интерфейса;
- `directoryMetadata` и метаданные дня — совместимость с прежними служебными полями.

Запись:

```json
{
  "id": "ex-uuid",
  "typeId": "type-subject",
  "activityId": "subject-id",
  "title": null,
  "groupIds": ["group-0"],
  "staffIds": ["teacher-uuid-1", "teacher-uuid-2"],
  "roomId": "room-id",
  "start": 540,
  "end": 580,
  "subgroup": "all",
  "event": false,
  "details": {}
}
```

Названия связанных объектов в записи не дублируются. `title` служит для свободного названия мероприятия/прежней записи вне справочника. `event` — подсказка совместимости редактора, не отдельная сущность хранения. Состав `staffIds` — точный набор назначений; удалённый сотрудник не восстанавливается по позиции в прежнем массиве. Совместное мероприятие — одна запись с несколькими `groupIds`. Подгруппы `a/b` не требуют постоянного состава учеников.

Новые ID формируются через UUID, с резервным генератором для окружений без crypto.randomUUID. Старые ID сохраняются. Уникальность старых записей проверяется в пределах даты, новые ID глобально случайные; ключ записи — дата + ID. ID каталога не пересоздаётся при переименовании. Исходные ID комнат, ранее вычисленные из имени, сохраняются как непрозрачные идентификаторы.

## Граница интерфейса

Существующий редактор пока работает с представлением `extras/events`, числовыми индексами групп и именами сотрудников. `openStorage()` — явный адаптер только семи ключей приложения; глобальное window.localStorage не подменяется. На чтении `decode()` строит это представление из ID. На записи `encode()` переводит выбранные имена в ID и валидирует связи. Имена на границе трактуются как явный выбор редактора; прежние ID не могут отменить новый выбор. Остальные служебные ключи проходят в браузерное хранилище без преобразования.

Таким образом, канонический документ единственный источник расписания; прежние массивы — временные представления в памяти. Настройки и неиспользуемые сейчас недельные шаблоны сохранены в прежнем формате. Это намеренная переходная граница; полный перевод всех редакторов на ID и CRUD типов/групп относится к последующим этапам.

## Сохранение и перенос существующих данных

При первом запуске читаются прежние семь ключей, документ преобразуется и проверяется, затем записывается одним setItem. Старые ключи остаются как аварийный исходный снимок, но при наличии `aspect_document_v1` больше не читаются. Автоматического сброса нет, разрешение пользователя на очистку тестовых данных не потребовалось.

Каждая запись через адаптер сначала готовит новый документ, проверяет даты, уникальность ID, ссылки и интервалы. Изменение состояния в памяти происходит только после успешного setItem. Это атомарность одной записи документа, не транзакция нескольких UI-операций. Расширенное восстановление, миграции следующих версий, общий undo, конкурентные вкладки и нагрузка десяти лет здесь не реализованы.

Текущий экспорт резервной копии продолжает получать полное совместимое представление через адаптер. Это сохраняет существующий формат v20, но не означает закрытия всех замечаний аудита к экспорту/импорту. Полная очистка через существующие настройки проходит через адаптер. Для возврата старой версии приложение не умеет читать новую схему: нужен экспорт v20 или удаление нового ключа с возвратом к старому снимку, что потеряет изменения после миграции. Самостоятельно откатывать опубликованный код поверх новых данных нельзя.

```sh
node school-aspect/tests/stage1.test.cjs
```

Проверяются модель и реальные обработчики встроенного скрипта в отдельном VM-контексте с имитируемыми DOM/localStorage. Пересоздание VM моделирует повторную загрузку скрипта. Браузерная проверка описывается отдельно и не подменяется этими тестами.
