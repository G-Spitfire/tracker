## Реализация

- В панели «Отсутствия» — одна форма: сотрудник, даты включительно, необязательная причина. Ниже список всех отсутствий с изменением и удалением. Соседние даты одного сотрудника с одинаковой причиной показаны одним периодом.
- Сохранение/редактирование периода изменяет только отметки отсутствия. Уроки, события, назначения и отсутствия других сотрудников сохраняются. При наложении нового периода на существующие отметки того же сотрудника приложение предупреждает перед обновлением.
- Отсутствия остаются в прежней канонической модели days[date].absences[staffId]. Отдельной сущности периода и миграции схемы не потребовалось. Пустая причина — допустимая строка; наличие отметки определяется по ключу, а не по тексту причины. Старые служебные подтверждения решения об отсутствии затронутой записи сбрасываются при новом указании отсутствия, чтобы предупреждение не скрывалось.
- «Массовая замена» открывает одно окно: два сотрудника, даты, поиск и список с галочками. В каждой строке дата/время, активность, группы/подгруппа, помещение, текущие ответственные. Изначально выбраны все найденные актуальные записи; скрытые отменённые/удалённые записи не включаются.
- До применения рассчитывается итоговое состояние всех выбранных записей. Предупреждения показываются в строках: сотрудник занят в другой записи, возникает новое пересечение между выбранными заменами, сотрудник отсутствует, уже назначен в этой записи. Изменение выбора пересчитывает предупреждения и сбрасывает подтверждение.
- При подтверждённом сохранении конфликты не запрещают замену. Невалидный сотрудник/период, одинаковые исходный и заменяющий сотрудники, пустой или устаревший выбор отклоняются.
- Заменяется только нужный staffId. Остальные ответственные сохраняются; уже назначенный заменяющий не дублируется. ID занятий, групп и справочников не меняются. Совместное мероприятие остаётся одной записью. Отсутствия не удаляются.
- Операции используют applySchedule этапа 2: один проверенный документ, одна запись, один снимок отмены, прежняя защита второй вкладки. Новые кнопки сохранения/удаления в панели помечены data-staff-mutation и обходят общий обработчик промежуточных записей, поскольку выполняют атомарную запись самостоятельно. Диалог массовой замены использует тот же прямой путь.
- Отсутствия и результаты замен входят в существующую полную резервную копию без изменения её версии. Дополнительного журнала замен нет.

Чистая логика находится в staff.js; интерфейс — в index.html. Архитектура этапов 1–3 сохранена.

Пройдено **27 + 12 + 16 + 18 = 73 проверки**. Исполнение — стандартная CommonJS-среда Node через доступный runtime (терминальная команда node отсутствует в PATH). VM-проверки реального скрипта интерфейса не считаются браузерными.

18 новых проверок покрывают:

1. Однодневное отсутствие без причины, неизменность назначений, сброс устаревшего служебного решения.
2. Период включительно и его отображение в списке.
3. Отсутствие в дни без расписания.
4. Изменение периода без потери других сотрудников и записей.
5. Удаление отсутствия без удаления расписания.
6. Перекрытия периодов и некорректные параметры.
7. Поиск всех назначений в уроках, подгруппах и едином мероприятии.
8. Изменение только выбранных записей.
9. Единое совместное событие, неизменные ID и остальные сопровождающие.
10. Занятость замены и новые одновременные назначения после замены.
11. Отсутствующая замена с пустой причиной; сохранение всех отметок отсутствия.
12. Уже назначенный заменяющий без дублирования и потери остальных.
13. Сохранение с предупреждениями и отказ при нарушенной целостности.
14. Одна запись для многодневной операции и полная одноуровневая отмена.
15. Ошибка хранилища без частичного результата.
16. Повторное открытие, сброс отмены, точное восстановление копии с отсутствиями/заменами.
17. Запрет операций из read-only вкладки.
18. Стандартные предупреждения интерфейса для отсутствующего второго ответственного и конфликтов после замены.

## Ограничения и оставшиеся вопросы

- Периоды — представление дневных отметок: соседние дни с одинаковой причиной объединяются. Отдельные пересекающиеся «заявки» одного сотрудника не хранятся. При изменении перекрывающих отметок требуется явное подтверждение.
- Прогноз массовой замены относится к занятости заменяющего сотрудника и четырём проверкам из ТЗ. Расчёт рабочего графика, произвольная вместимость помещений и старые исключения комнат по названию не перерабатывались. Существующий механизм доски продолжает показывать свои остальные предупреждения.
- Один писатель и ограничения localStorage остаются как в этапе 2. Старые вкладки приложения необходимо обновить перед редактированием.
- При изменении параметров/выбора подтверждение операции сбрасывается; при внешнем изменении данных сохранение блокируется прежней защитой.
- Перекрытие карточек на доске, PDF и прочие незакрытые пункты исходного аудита относятся к следующим этапам.

Этап 4 завершён в согласованном объёме. Для перехода к этапу 5 требуется подтверждение пользователя.
