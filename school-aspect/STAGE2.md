## Уточнённый объём

По решению пользователя проверяется один год, вместо десяти. Один формат резервной копии, один основной браузер; автоматического объединения вкладок нет. Отмена относится к изменениям расписания и составным операциям, один уровень, только до перезагрузки. Настройки/справочники не отменяются; их изменение сбрасывает прежнюю отмену. Старые даты автоматически не удаляются. Эти прямые решения зафиксированы в PROJECT.md. Этап 3 не начинался.

## Что сделано

- Резервная копия: `{format:"aspect-backup",version:1,document:...}`. Внутри полный канонический документ: расписания, назначения, отсутствия, все справочники, настройки и ID. Старые v20-копии не импортируются, новое сообщение объясняет нужный формат.
- Восстановление: чтение и проверка файла до подтверждения и записи, затем замена целого документа одним setItem. Невалидный JSON, версия, даты, интервалы, дубликаты ID, неизвестные связанные сотрудники/комнаты/группы/типы, структура и основные настройки отклоняются. Частичного восстановления нескольких ключей больше нет.
- Операция интерфейса собирает записи в промежуточное представление. Только после завершения обработчика формируется и проверяется новый документ и выполняется одна запись. Ошибка посреди операции или отказ записи оставляет прежнее состояние хранилища. Интерфейс восстанавливает согласованные данные, сохраняя исходный черновик.
- Кнопка «Отменить»: возвращает документ целиком, включая взаимосвязанные изменения составной операции. Предыдущее состояние хранится только в памяти. После перезагрузки, восстановления/очистки или промежуточного изменения справочников отмена сбрасывается. При недоступности кнопка отключена с пояснением.
- Web Locks разрешает запись только одной вкладке приложения. Дополнительная вкладка показывает режим просмотра; для редактирования надо закрыть первую и обновить вторую. Перед любой записью/отменой проверяется, что сохранённый документ не изменился извне. Событие storage блокирует устаревшую страницу и сбрасывает отмену. Если API блокировок недоступен, запись запрещена с объяснением, небезопасного запасного режима нет.
- Внутреннее хранение уплотнено: записи представлены массивами полей в оболочке storageVersion=1, без повторения названий полей у каждого занятия. При чтении восстанавливается полная модель. Резервная копия остаётся обычным полным JSON. Прежний канонический документ этапа 1 читается и переводится автоматически; новая версия хранилища не читается старым приложением.

## Год данных

Синтетический набор: **260 учебных дней × 6 групп × 8 записей = 12 480 записей**. Экспорт, очистка, восстановление, редактирование и повторное открытие прошли; все ID и связи сравнивались.

| Показатель | Результат |
|---|---:|
| Полный документ до уплотнения, оценка UTF-16 | 6 874 198 байт |
| Уплотнённое хранение, оценка UTF-16 | 4 153 614 байт (3,96 МиБ) |
| Уплотнённый JSON, UTF-8 | 2 126 765 байт |
| Полная читаемая резервная копия, UTF-8 | 6 577 333 байт |
| Последний измеренный прогон годового сценария | 677 мс |

Это измерение стенда в памяти, не измерение фактической браузерной квоты. Размер рабочего документа уменьшен примерно на 40%. Реальные длинные названия, много ответственных и дополнительные сведения увеличат объём; хранилище общее для origin, на котором находятся и другие приложения tracker. Год в таком составе помещается в ориентир 5 МиБ для localStorage, но запас ограничен. При росте объёма техническое решение — IndexedDB с транзакциями; в этом этапе переход не делался. Переполнение не очищает и не обрезает данные: операция отклоняется, выводится сообщение и предлагается экспорт.

## Ограничения

- Запись разрешена одной вкладке; переход права записи требует закрытия первой и обновления второй. Для проверки/экспорта можно открыть дополнительные вкладки.
- Перед использованием новой версии следует обновить все старые вкладки. Страницы этапа 1 не участвуют в Web Locks; новая вкладка обнаружит изменение их данных, но старый код нельзя считать частью нового протокола защиты.
- Формат резервной копии проверяет корректность структуры и связей, но не доказывает происхождение/авторство файла. Импорт не загружает внешние ресурсы.
- Операции редакторов, назначенные через onclick/onchange, объединяются перехватчиком пользовательского события. При добавлении новых обработчиков через addEventListener разработчик должен явно использовать atomic().
- Прямые служебные ключи миграций и дата скачивания не являются частью канонических данных. Старые снимки могут занимать дополнительное место; автоматически они не удаляются.
- Незавершённый черновик, вкладки с разными версиями кода и отказ Web Locks требуют внимания интерфейса; незаметной перезаписи новая версия не допускает.
- Ошибки копирования мероприятий, режим «Объединить», массовые замены, PDF и остальные замечания исходного аудита остаются для следующих этапов.
