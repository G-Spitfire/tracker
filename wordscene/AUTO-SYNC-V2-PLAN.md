# WordScene — безопасная автоматическая синхронизация (план реализации)

Статус: проектирование. **Не подключено к рабочему приложению.** Базовая ветка: `feature/wordscene-cloud-sync`.

## Цель
Ребёнок учит слова без кнопок управления копиями. Локальная работа доступна без сети; прогресс одного Firebase UID синхронизируется между устройствами, не теряя подтверждённых результатов.

## Что установлено по исходному коду
- `word-scenes-v5` — единый локальный снимок, включающий `words`, `reviewCycle`, `session` и другие поля.
- Текущий `cloud-sync.js` сравнивает снимки целиком, останавливается при расхождении и требует выбора версии.
- Firestore хранит `users/{uid}/wordscene/state` с `revision`. Существующий документ **не изменять и не удалять**.
- `profile-store.js` изолирует гостевой и авторизованный локальные профили.
- В Safari проверены вход, чтение облака, обнаружение конфликта, экспорт JSON и гостевой режим; двусторонняя синхронизация и офлайн-сценарии ещё не проверены.

## Предлагаемый протокол v2
1. При каждом **подтверждённом учебном действии** записывать неизменяемое событие в локальный outbox до отображения успешного сохранения. Каждое событие имеет `eventId` (случайный UUID), `uid`, `deviceId`, `wordId`, `kind`, `payload`, `createdAt` и версию схемы. Не использовать время клиента для разрешения конфликтов.
2. Отправлять события в отдельную коллекцию `users/{uid}/wordsceneEvents/{eventId}` с идемпотентным созданием: повторная отправка того же ID не создаёт дубль. Запись только для текущего UID; правила Firestore должны проверяться отдельно до включения.
3. Получать события с других устройств и применять детерминированный reducer. Счётчики и история выводятся из объединения уникальных событий, а не из сложения уже агрегированных снимков. Не предполагать, что поля `words` можно безопасно сливать по принципу «максимум».
4. Активная `session` остаётся локальной до завершения занятия; при завершении формируются учебные события. Возобновление незавершённого занятия на другом устройстве не обещать в v2.
5. Очередь хранить долговечно локально; отправлять при наличии сети, входе в приложение и восстановлении связи. Событие удалять из очереди только после подтверждения сервером. При сбое не блокировать обучение.
6. UI: нейтральные статусы «Сохранено» / «Сохранится при подключении»; диагностика, экспорт и восстановление доступны только в скрытом техническом разделе.
7. Миграция: существующий `state` читать как исходную копию, перед первой миграцией экспортировать/архивировать **обе** версии, если они расходятся. Не превращать старый агрегированный снимок в фиктивные учебные события без доказанной обратимой схемы. Нужен явный одноразовый baseline и версия миграции; до проверки не писать в рабочий Firestore.
8. Смена UID: остановить все отправки, отделить outbox по UID, затем переключить локальный профиль. Гостевые события никогда не отправлять автоматически в чужой аккаунт.

## Обязательные проверки перед подключением
- Повторная отправка одного eventId не удваивает результат.
- Одновременные события двух устройств для одного слова не теряются.
- Offline → restart → online: очередь и результаты сохраняются.
- Смена аккаунта во время запроса не переносит чужие события.
- Незавершённая сессия не повреждается при входящих событиях.
- Старая ревизия Firestore и текущий локальный прогресс остаются доступны после миграции.
- Ошибки доступа, квоты, повреждённое хранилище и повторное подключение.
- Мобильный Safari, обновление вкладки и перезапуск PWA.

## Этапы
A. Исследовать точки записи учебных результатов и схему `state-guard.js`; зафиксировать reducer и тестовые инварианты.
B. Реализовать локальный журнал/outbox и тесты без Firebase.
C. Реализовать изолированный Firestore-адаптер v2 и эмуляторные тесты; подготовить отдельные правила безопасности.
D. Добавить безопасную миграцию и упрощённый UI за feature flag (по умолчанию выключен).
E. Протестировать в браузере и на двух устройствах с тестовым UID. Только после этого обсуждать включение.

## Ограничения
Никаких изменений `main`, существующих документов Firebase или продакшн-правил. Не включать автоматическую синхронизацию до прохождения тестов.
