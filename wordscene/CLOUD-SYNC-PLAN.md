# WordScene — облачная синхронизация

Статус: тестовая реализация в `feature/wordscene-cloud-sync`; не публиковать в рабочее приложение до прохождения проверки Firebase и пользовательского smoke-теста. Firebase Rules этим изменением не затрагиваются.

## Существующее поведение
- Гостевой режим остаётся основным: обучение доступно без аккаунта и сети.
- Основной локальный ключ: `word-scenes-v5`; не переименовывать и не очищать.
- Валидировать состояние через `WordSceneState.valid(state, words.length)`.
- Словарь и иллюстрации не отправлять в Firestore.

## Модель
- Firebase Authentication: каждый пользователь получает собственный UID.
- Документ: `users/{uid}/wordscene/state`, поля `schemaVersion`, `revision`, `updatedAt`, `payload`.
- События аналитики в отдельной подколлекции, после запуска базовой синхронизации.
- Проверить фактический размер payload: лимит документа Firestore 1 MiB. При превышении перейти к разбиению по словам.

## Первая миграция
1. Сделать экспорт JSON-копии локального состояния, проверить структуру и возможность восстановления.
2. Авторизоваться, проверить UID и правила доступа.
3. Если облако пустое — записать локальный снимок транзакцией с ревизией 1.
4. Если облако уже содержит состояние — не заменять автоматически. Предложить пользователю сохранить обе копии и выбрать источник.
5. После подтверждения загрузить выбранное состояние в localStorage с сохранением текущего ключа; проверить восстановление после перезапуска.

## Последующие записи
- Локальная запись первична, не зависит от сети.
- Каждая облачная запись использует транзакцию с проверкой revision.
- Если revision изменился, сохранять обе версии и останавливать автоматическую перезапись; слияние учебных состояний не делать.
- Сохранять очередь ожидающих загрузки изменений при офлайне. Не объявлять синхронизацию успешной до подтверждения сервера.
- Не помещать реальные прогрессы, UID, токены или Firebase credentials в Git.

## Реализация тестовой ветки

- `cloud-firestore.js` выполняет чтение и транзакционную запись, проверяет схему, ревизию и размер payload (защитный порог 900 KiB); вложенные массивы кодируются обратимым тегом для совместимости с Firestore.
- `cloud-sync.js` реализует локально-первичную синхронизацию: отправку локальных изменений, получение удалённых изменений, ожидание завершения активного занятия и остановку при конфликте.
- При конфликте обе версии фиксируются в localStorage и доступны для скачивания одним JSON-файлом. После скачивания пользователь выбирает локальный или облачный снимок. Устаревший снимок нельзя применить; перед восстановлением сохраняется локальная резервная копия.
- Настройки синхронизации привязаны к UID. Гостевое обучение не зависит от Firebase.
- `profile-store.js` сохраняет совместимость с ключом `word-scenes-v5`, а локальные копии гостя и каждого UID ведёт раздельно. При смене аккаунта предыдущая копия сохраняется, новая загружается; гостевые данные не привязываются к аккаунту автоматически. Явный перенос гостевого прогресса сохраняет обе копии. Настройки синхронизации разделены по UID и проверяются по активному локальному профилю.
- Автоматические тесты запускаются: `node --test wordscene/tests/*.test.cjs`.
- Реальные Firebase Rules/Auth и два отдельных пользовательских аккаунта нужно подтвердить в браузере с разрешённым тестовым доступом. Не считать локальную имитацию транзакций доказательством работы production Firebase.

## Перед подключением
- Уточнить реальные Firebase config и правила Firestore из существующей инфраструктуры.
- Проверить точный размер `word-scenes-v5`, ограничения iOS PWA и поведение нескольких вкладок.
- Написать тесты: гость, первый вход, пустое облако, существующее облако, офлайн, конфликт ревизий, повреждённые данные, выход из аккаунта.
- Отдельно согласовать UX выбора между локальной и облачной копиями.

`cloud-migration.js` содержит только чистые функции резервной копии и обнаружения конфликтов. Он не загружается `index.html` и не меняет данные.
