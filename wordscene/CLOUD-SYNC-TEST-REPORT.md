# WordScene — отчёт проверки облачного резервирования

**Дата:** 31 октября 2026 года

**Ветка:** `feature/wordscene-auto-backup` от актуального `main`

**Feature flag:** `AUTO_BACKUP_ENABLED=false` — автоматическая отправка в приложение не включена.

## Реализовано

- Локальный снимок остаётся основным и сохраняется независимо от сети. После успешного сохранения занятия приложение планирует облачную копию с задержкой 2,2 секунды; предусмотрен повтор после возвращения сети и при открытии приложения.
- Облачная запись использует транзакцию с ожидаемой ревизией. После записи клиент перечитывает снимок и сверяет ревизию и содержимое, прежде чем пометить копию актуальной.
- Более новая удалённая версия не скачивается поверх локальной. При конфликте обе версии архивируются и автоматическая запись останавливается.
- На новом пустом профиле существующая облачная копия предлагается взрослому для восстановления. Непустой локальный прогресс не заменяется автоматически; перед явным восстановлением UI подтверждает действие и сохраняет текущие байты.
- Профили и параметры резервирования изолированы по Firebase UID. Словарь и иллюстрации не отправляются.
- Новая функция скрыта за выключенным флагом до прохождения интеграционных и браузерных проверок. Правила и данные Firebase не менялись.

## Выполненные проверки

- `node --test wordscene/tests/*.test.cjs` — **35 тестов пройдены, 0 ошибок**. В том числе: ревизионные конфликты, смена аккаунта, сетевой сбой, перезапуск после offline, восстановление отправки, сохранность активной сессии и явное восстановление.
- `node --check wordscene/*.js` — синтаксическая проверка JS-файлов прошла.
- Встроенный скрипт `index.html` разобран через `new Function` — прошёл.
- `git diff --check` — прошёл.
- Сравнены деревья локальной ветки и опубликованной GitHub-ветки — совпадают.

## Не проверено

- Firebase Emulator и правила Firestore. В окружении есть Firebase CLI 15.34.2, но Java 17; для этой версии CLI нужен JDK 21+. Доступ к действующим правилам проекта не использовался и сами правила не менялись.
- Реальные браузерные сценарии, включая Safari/iPhone. Попытка открыть локальный сервер в предоставленном браузере была отклонена политикой доступа к URL; обходить ограничение не стали.
- Реальный тестовый Firebase UID, offline/restart на физическом iPhone и публикация приложения.

## Вывод

Клиентская логика покрыта unit-тестами, но готовность к использованию детьми не подтверждена. Оставить feature flag выключенным до проверки правил в Emulator и полного сценария входа, резервирования и восстановления в Safari на iPhone с тестовым аккаунтом.
