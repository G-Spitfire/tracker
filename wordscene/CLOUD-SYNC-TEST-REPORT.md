# WordScene — отчёт проверки облачного резервирования

**Обновлено:** 1 ноября 2026 года

**Ветка:** `feature/wordscene-auto-backup`; разошлась с `main`, черновик PR #21

**Feature flag:** `AUTO_BACKUP_ENABLED=false` — автоматическая отправка в приложение не включена.

## Реализовано

- Локальный снимок остаётся основным и сохраняется независимо от сети. После успешного сохранения занятия приложение планирует облачную копию с задержкой 2,2 секунды; предусмотрен повтор после возвращения сети и при открытии приложения.
- Облачная запись использует транзакцию с ожидаемой ревизией. После записи клиент перечитывает снимок и сверяет ревизию и содержимое, прежде чем пометить копию актуальной.
- Более новая удалённая версия не скачивается поверх локальной. При конфликте обе версии архивируются и автоматическая запись останавливается.
- На новом пустом профиле существующая облачная копия предлагается взрослому для восстановления. Непустой локальный прогресс не заменяется автоматически; перед явным восстановлением UI подтверждает действие и сохраняет текущие байты.
- Профили и параметры резервирования изолированы по Firebase UID. Словарь и иллюстрации не отправляются.
- Новая функция скрыта за выключенным флагом до прохождения интеграционных и браузерных проверок. Правила и данные Firebase не менялись.

## Выполненные проверки

- GitHub Actions `WordScene backup tests`: последний запуск на коммите `d840f83` завершился успешно. Предыдущий запуск падал из-за устаревшего ожидания пустого профиля после первого входа; тест обновлён под автоматический перенос гостевого прогресса. В том числе: ревизионные конфликты, смена аккаунта, сетевой сбой, перезапуск после offline, восстановление отправки, сохранность активной сессии и явное восстановление.
- Добавлены GitHub Actions проверки Firestore Emulator на Java 21: запись/чтение собственного документа разрешены; чтение/запись другого UID, анонимный доступ и другие документы запрещены. Изолированный fixture ещё не запускался в CI для этой ветки.
- `node --check wordscene/*.js` — синтаксическая проверка JS-файлов прошла.
- Встроенный скрипт `index.html` разобран через `new Function` — прошёл.
- `git diff --check` — прошёл.
- Сравнены деревья локальной ветки и опубликованной GitHub-ветки — совпадают.

## Не проверено

- Локальный запуск Firebase Emulator: Firebase CLI 15.34.2 завершился с ошибкой, что нужен JDK 21+, а в окружении Java 17. Действующие правила проекта не представлены в репозитории; их совместимость и правила других приложений не проверены, ничего в Firebase не менялось.
- Проверка правил в Emulator CI будет проверять только отдельный WordScene fixture. Перед включением нужно проверить полный ruleset проекта: более широкое разрешающее совпадение может дать доступ несмотря на этот узкий блок.
- Реальные браузерные сценарии, включая Safari/iPhone. Попытка открыть локальный сервер в предоставленном браузере была отклонена политикой доступа к URL; обходить ограничение не стали.
- Реальный тестовый Firebase UID и весь пользовательский поток Firebase Authentication → первое резервирование → повторная запись → offline/restart/online → восстановление. Локальные тесты покрывают клиентскую логику, но не реальный Firebase Auth/Firestore.
- Offline/restart на физическом iPhone и публикация приложения.

## Вывод

Клиентская логика покрыта unit-тестами, но готовность к использованию детьми не подтверждена. Оставить feature flag выключенным до проверки правил в Emulator и полного сценария входа, резервирования и восстановления в Safari на iPhone с тестовым аккаунтом.

## Изменения 1 ноября 2026

- `profile-store.js`: при первом входе в новый UID копирует гостевой прогресс в профиль аккаунта, сохраняя гостевую копию. Уже существующий профиль UID не затирается.
- `cloud-ui.js`: однократное предложение входа или продолжения без аккаунта. При отказе предложение не повторяется на каждом запуске.
- **Пока не реализовано/не подтверждено:** включение `AUTO_BACKUP_ENABLED`, автоматический первый upload после входа в рабочем режиме, полный сценарий на Safari/iPhone, объединение с последней `main`, проверка созданных детских Firebase Auth аккаунтов.
- **Решение о публикации:** не публиковать до успешных интеграционных проверок и защиты локального прогресса Полины.

Устаревшие пункты выше о непроверенном Emulator CI относятся к состоянию на 31 октября: позднее GitHub Actions с Java 21 и полной копией предоставленных правил Firestore прошли успешно (run #17). Это проверка предоставленного ruleset в эмуляторе, не доказательство неизменности текущих production Rules.
