# Правила Firebase для подготовленного выпуска Левели

Файл `../firestore.rules` применён к рабочему проекту после получения, сохранения и сравнения действующих серверных правил. Исходные ветки содержали только тестовые варианты, однако серверные правила удалось получить через официальный Firebase Rules API. Их точная резервная копия и прежний ruleset сохранены для отката вне Git. Подробности: [проверка рабочего Firebase](../leveli/FIREBASE-VALIDATION.md).

## Контракт применённых правил

- `schoolGrades/{uid}` и `profiles/{uid}`: владелец читает свой документ; клиентская запись, удаление и получение списка запрещены. Загрузка дневника доверенным Admin SDK продолжает использовать IAM, а не клиентские правила.
- `footballSnapshots/{id}`: авторизованный клиент читает документы и список с лимитом не более 120; клиентская запись запрещена.
- `users/{uid}/wordscene/state`: только владелец читает и пишет копию. Другие документы, списки и удаление запрещены. Первая ревизия — 1, далее строго +1. Обязательны схема 1, серверная метка времени, числовое время клиента и полезная нагрузка версии 5.
- Проверяются обязательные поля, типы основных структур, количество слов не более 500 и отсутствие лишних полей оболочки. Неизвестные старые поля внутри полезной нагрузки сохраняются в пределах 32 верхних ключей.
- Остальные пути закрыты по умолчанию. Локальное футбольное избранное не превращается в облачный writer.

Все внутренние элементы произвольной карты слов правила не проверяют; полная проверка учебного состояния остаётся также в `state-guard.js`. Клиент ограничивает размер полезной нагрузки 900 KiB; общий предел документа устанавливает Firestore. Правила не превращают пользовательский учебный прогресс в подтверждённый школьный результат.

## Проверка

Реальный Firestore Emulator 1.22.0, Firebase SDK 13.1.0, Firebase CLI 15.34.2, rules-unit-testing 6.0.0, Java 21. Все 7 групп проверок пройдены: компиляция; два владельца и анонимный клиент; схема, типы, ревизии, метки времени; приватность и запрет изменения оценок; чтение футбола; закрытие неизвестных путей; автоматическое создание копии через существующий движок и настоящий транспорт, обратное чтение вложенных массивов и конфликт ревизии.

Команда из корня репозитория, при установленных тестовых инструментах:

```sh
firebase emulators:exec --only firestore --project demo-leveli-release-check --config firebase.emulator.json 'node --test leveli/tests/firestore-rules.cjs'
```

Здесь намеренно используется проект `demo-...`, localhost и отдельная конфигурация эмулятора. Инструменты тестирования не добавлены в зависимости приложения; сборка приложения не появилась.

## Порядок следующего изменения рабочего проекта

1. Получить явное подтверждение пользователя на выпуск и изменение правил.
2. Сохранить текущий развёрнутый набор правил из Firebase, сравнить с кандидатом. Отсутствие файла в Git не означает отсутствие правил на сервере. Если обнаружатся дополнительные нужные пути или клиентские writer-механизмы, сохранить их и повторить проверки; не заменять рабочие правила вслепую.
3. Применить проверенные изменения правил и подтвердить доступ двух рабочих аккаунтов и отсутствие доступа к чужим документам.
4. Только затем включить `AUTO_BACKUP_ENABLED`, проверить клиент и опубликовать согласованную версию приложения.

В текущей локальной ветке автокопии клиента отключены до согласования выпуска. Рабочие правила Firestore изменены с разрешения пользователя и проверены; реальный прогресс детей и опубликованный клиент не изменялись. Семь рабочих сценариев на временных искусственных аккаунтах пройдены, созданные тестовые данные удалены.

Официальные материалы: [проверка правил в эмуляторе](https://firebase.google.com/docs/firestore/security/test-rules-emulator), [управление правилами](https://firebase.google.com/docs/rules/manage-deploy).


## Финальный кандидат — 2 ноября 2026

По явному разрешению пользователя автоматическое резервирование WordScene включено в клиенте (`AUTO_BACKUP_ENABLED=true`) после проверки рабочих правил Firebase. После входа копии создаются автоматически; локальный прогресс и отдельные профили сохранены. Новая облачная версия не заменяет локальную молча. Это состояние рабочей ветки; прежние сведения об отключённом флаге описывают этап до этой даты. Публикация, слияние в main и релиз не выполнялись и требуют отдельного разрешения.
