# Проверка безопасности WordScene в Firebase

**Внимание:** это фрагмент для включения в существующие Firestore Rules, а не полная замена правил проекта `family-school-grades`. Не удалять действующие правила Leveli и школьных оценок.

Внутри существующего `match /databases/{database}/documents`:

```javascript
match /users/{uid}/wordscene/{documentId} {
  allow read, write: if request.auth != null
    && request.auth.uid == uid
    && documentId == 'state';
}
```

**Важное ограничение:** это минимальная проверка владельца, но не строгая валидация структуры и размера payload. Перед production необходимо добавить проверку схемы, полей и размера либо вынести запись в доверенный сервер. Не публиковать эти правила без ревью всей действующей конфигурации.

## Тесты в Firebase Emulator Suite

1. Пользователь A читает и пишет `users/A/wordscene/state` — разрешено.
2. Пользователь B читает и пишет `users/A/wordscene/state` — запрещено.
3. Неавторизованный клиент читает и пишет `users/A/wordscene/state` — запрещено.
4. Пользователь A пытается писать `users/B/wordscene/state` — запрещено.
5. Пользователь A пытается писать `users/A/wordscene/other` — запрещено.
6. Существующие разрешённые операции Leveli и школьных оценок продолжают работать.
7. Проверить ограничения на размер документа (1 MiB) и корректность структуры.

## Условия запуска

- Получить и сохранить резервную копию текущих Firestore Rules.
- Проверить правила в эмуляторе и выполнить регрессионные тесты действующих приложений.
- Не подключать настоящие аккаунты WordScene до прохождения проверок.
- Не использовать реальные детские данные в тестах.
