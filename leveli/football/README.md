# Футбольный модуль «Левели»

Функциональные требования: консолидированное ТЗ v1.2. Навигация модуля — «Обзор / Команды / Игроки». Исторические «Разбор игры» и футбольные викторины в эту версию не входят.

## Состав

- `normalize.py` — нормализация ответов football-data.org v4 во внутреннюю схему. Неизвестные числа остаются `null`; логотипы и фото исключены до подтверждения прав.
- `adapter.py` — серверный клиент, ограничение частоты, повторные попытки, кеш последнего валидного снимка и подготовка документов Firestore.
- `update_snapshots.py` — ручное обновление выбранных турниров/сезона и экспорт JSON. Ничего не записывает в Firebase.
- `probe.py` — read-only проверка API; ограничение запросов не ниже 6,1 с. Таблицы/матчи — по умолчанию, `scorers` требует отдельного opt-in.
- `firebase_sync.py` — импорт JSON только в локальный Firestore Emulator. Требует `FIRESTORE_EMULATOR_HOST=localhost:8080` (или loopback) и `FIREBASE_PROJECT_ID=demo-leveli-football`; реальные проекты и внешние адреса отклоняются.
- `ui.js` и `snapshot_data.mjs` — интерфейс футбола, чтение Firebase-снимков по авторизованному аккаунту и преобразование формата экспорта. Сначала читается ограниченный список снимков; если правила запрещают listing, используется прямое чтение ожидаемых ID. Последние подтверждённые снимки кешируются для offline/stale режима. Клиент не обращается к football-data.org и не может записывать снимки.
- `favorites_sync.mjs` — проверенный контракт синхронизации избранного по `users/{auth.uid}/privatePreferences/football`: проверка UID, ограничение списка и обнаружение конфликтов между устройствами. Сетевого writer нет; локальное избранное остаётся UID-разделённым. Для включения межустройственной записи нужно отдельно проверить действующие Firebase Rules и получить разрешение на production write.
- `demo-snapshots.json` — искусственные данные только для визуальной проверки при URL-параметре `?football-demo=1`; они не попадают в пользовательский кеш.

## API и безопасность

Ключ хранится на машине/сервере обновления в переменной `FOOTBALL_KEY`. Не добавлять его в HTML, JavaScript, экспортируемый JSON, `.env` или Git. Все шесть целевых соревнований перечислены в Free Tier; в нём указаны таблицы, расписания и результаты, лимит — 10 вызовов в минуту. На текущей официальной странице football-data.org `Goal scorers` перечислены только в `Free + Deep Data` за €29/месяц, не в базовом Free. Доступность конкретного ключа может отличаться из-за его фактической подписки/разрешений; успешный ответ сам по себе не подтверждает бесплатный план. Поэтому scorer-запрос отключён по умолчанию и закрыт за отдельным флагом, без покупки или переключения тарифа. Приложение отображает scorer-данные только если их снимок уже предоставлен.

Клиент выдерживает интервал не менее 6,1 секунды между запросами и обрабатывает `Retry-After`. API требует регистрации и принятия условий провайдера. Обязательная атрибуция: «Football data provided by the Football-Data.org API» (указана в интерфейсе). Логотипы команд и фото игроков не сохраняются и не отображаются: условия требуют отдельно подтвердить права у владельцев изображений. Пока используются инициалы.

Рекомендуемый цикл — один ежедневный ручной запуск на сервере, при необходимости чаще в дни матчей. Облачное расписание не подключено: для него нужно отдельно выбрать допустимое бесплатное исполнение и проверить лимиты Firebase. Интерфейс читает документы из `footballSnapshots`; он не создаёт и не обновляет их. В этой задаче запись в production, изменение Firestore Rules и биллинг не выполняются.

Формат снимка:

```json
{
  "schemaVersion": 1,
  "source": "football-data.org",
  "league": "PL",
  "season": 2026,
  "endpoint": "standings",
  "fetchedAt": "2026-10-31T08:00:00Z",
  "count": 0,
  "items": []
}
```

Время `fetchedAt` — момент запроса к источнику, а не время матча. Данные старше 36 часов помечаются как устаревшие; offline-экран использует последний валидный локальный снимок, указывая его дату. Отсутствующие/закрытые тарифом метрики не заменяются нулём.

## Запуск

```sh
read -s FOOTBALL_KEY
export FOOTBALL_KEY
python3 leveli/football/update_snapshots.py --league PL --season 2026
```

Для нескольких целевых турниров повторите `--league`: `PL`, `PD`, `SA`, `BL1`, `FL1`, `CL`. JSON готов к импорту в коллекцию `footballSnapshots`; импортёр по-прежнему принимает только локальный Firestore Emulator. Production write путь не реализован. Endpoint бомбардиров блокируется без отдельного флага и не входит в штатное бесплатное обновление.

Тесты без API/Firebase:

```sh
python3 -m unittest discover -s leveli/football/tests -v
node --test leveli/football/tests/test_ui_data.mjs
```

Проверка браузерного демо на локальном HTTP-сервере: открыть `leveli/?football-demo=1`. В обычном режиме без Firestore-снимков интерфейс показывает пустые состояния, не демонстрационные числа.
