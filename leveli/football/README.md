# Футбольный модуль «Левели»

Функциональные требования: консолидированное ТЗ v1.2. Стартовый экран модуля — «Мой футбол»; разделы «Обзор / Команды / Игроки» сохранены. Исторические «Разбор игры» и футбольные викторины в эту версию не входят.

## Состав

- `normalize.py` — нормализация ответов football-data.org v4 во внутреннюю схему. Неизвестные числа остаются `null`; логотипы и фото исключены до подтверждения прав.
- `adapter.py` — системный `curl` через `subprocess` для сетевых запросов, ограничение частоты, повторы, кеш и подготовка документов. Ключ передаётся curl через stdin, не через аргументы и не сохраняется в файлах.
- `update_snapshots.py` — ручное обновление одного или всех шести турниров и экспорт JSON. Запрашивает ключ скрытым вводом, показывает прогресс и ничего не записывает в Firebase.
- `probe.py` — read-only проверка бесплатных методов API; показывает каждый запрос и ошибку, использует те же тайм-ауты и повторы, что загрузчик. Для CL проверяет только матчи.
- `firebase_sync.py` — импорт JSON только в локальный Firestore Emulator. Требует `FIRESTORE_EMULATOR_HOST=localhost:8080` (или loopback) и `FIREBASE_PROJECT_ID=demo-leveli-football`; реальные проекты и внешние адреса отклоняются.
- `ui.js` и `snapshot_data.mjs` — интерфейс футбола, чтение Firebase-снимков по авторизованному аккаунту и преобразование формата экспорта. Сначала читается ограниченный список снимков; если правила запрещают listing, используется прямое чтение ожидаемых ID. Последние подтверждённые снимки кешируются для offline/stale режима. Клиент не обращается к football-data.org и не может записывать снимки.
- Экран «Мой футбол» показывает до трёх избранных команд из всех доступных турнирных снимков, а также «Зенит» и московское «Динамо» из отдельного каталога. Команды Лиги чемпионов можно найти по календарю даже без таблицы. Для каждой команды отображаются только полученные место/очки, результаты и матчи; отсутствующие поля обозначаются текстом. Если у разных турниров доступны разные сезоны, экран использует выбранный сезон там, где он загружен, иначе последний имеющийся снимок.
- `players-catalog.json` — отдельный каталог 60 действующих футболистов и два проверенных российских клуба. Записи игроков содержат устойчивый ID, имя, страну, позицию, клуб, дату проверки и официальный источник; статистика игроков в каталог не добавляется. Составы 42 ранее существовавших игроков перепроверены по UEFA 2026/27. Добавлены Месси, Роналду, игроки «Арсенала» и «Ливерпуля», а также игроки «Зенита» и московского «Динамо». «Зенит» и «Динамо» доступны в поиске и избранном даже без футбольных снимков; для РПЛ прямо сообщается, что таблица и календарь пока не подключены. Для команд шести поддерживаемых соревнований матчи связываются по проверенному football-data.org ID либо точному имени. Сведения каталога нужно обновлять вручную по указанным ссылкам.
- Раздел «Игроки» упорядочен как «Мои игроки / Популярные футболисты / Каталог и поиск». «Обзор» не дублирует блоки избранного. Избранные команды и игроки (до трёх каждого типа) сохраняются в прежнем ключе `localStorage` текущего браузера отдельно для гостя/UID аккаунта. Между устройствами выбор не синхронизируется: writer Firebase не подключён.
- `favorites_sync.mjs` — проверенный контракт синхронизации избранного по `users/{auth.uid}/privatePreferences/football`: проверка UID, ограничение списка и обнаружение конфликтов между устройствами. Сетевого writer нет; локальное избранное остаётся UID-разделённым. Для включения межустройственной записи нужно отдельно проверить действующие Firebase Rules и получить разрешение на production write.

## Данные РПЛ

Текущий источник таблицы и календаря РПЛ не подключён. Проверка открытого метода OpenLigaDB `getavailableleagues` показала исторический RFPL 2011, но не сезон 2026/27; поэтому он не подходит для актуального расписания. Официальный сайт РПЛ публикует таблицу и матчи, но указывает, что права на материалы принадлежат РПЛ и использование требует согласования. API-Football предлагает бесплатный тариф с дневным лимитом, однако его условия не предоставляют разрешение на публикацию данных пользователям и оставляют необходимость получать права у правообладателей. До подтверждения условий и лицензии источник не интегрируется; клубы и профили российских игроков остаются доступны без результатов.

## API и безопасность

Ключ хранится на машине/сервере обновления в переменной `FOOTBALL_KEY`. Не добавлять его в HTML, JavaScript, экспортируемый JSON, `.env` или Git. Все шесть целевых соревнований перечислены в Free Tier; в нём указаны таблицы, расписания и результаты, лимит — 10 вызовов в минуту. На текущей официальной странице football-data.org `Goal scorers` перечислены только в `Free + Deep Data` за €29/месяц, не в базовом Free. Доступность конкретного ключа может отличаться из-за его фактической подписки/разрешений; успешный ответ сам по себе не подтверждает бесплатный план. Поэтому пользовательский загрузчик не запрашивает `scorers` и не включает платные методы. Приложение отображает scorer-данные только если их снимок уже предоставлен.

Клиент выдерживает интервал не менее 6,1 секунды между запросами и обрабатывает `Retry-After`. Запрашиваются бесплатные таблицы и матчи. Для CL загружаются только матчи, так как API не предоставляет таблицу для кубковых соревнований. API требует регистрации и принятия условий провайдера. Обязательная атрибуция: «Football data provided by the Football-Data.org API» (указана в интерфейсе). Логотипы команд и фото игроков не сохраняются и не отображаются: условия требуют отдельно подтвердить права у владельцев изображений. Пока используются инициалы.

Рекомендуемый цикл — один ежедневный ручной запуск на сервере, при необходимости чаще в дни матчей. Облачное расписание не подключено: для него нужно отдельно выбрать допустимое бесплатное исполнение и проверить лимиты Firebase. Интерфейс читает документы из `footballSnapshots`; он не создаёт и не обновляет их. В этой задаче запись в production, изменение Firestore Rules и биллинг не выполняются.

Формат снимка:

```json
{
  "schemaVersion": 1,
  "source": "football-data.org",
  "league": "PL",
  "season": 2026,
  "endpoint": "standings",
  "fetchedAt": "2026-10-31T08:00:00Z",
  "count": 0,
  "items": []
}
```

Время `fetchedAt` — момент запроса к источнику, а не время матча. Данные старше 36 часов помечаются как устаревшие; offline-экран использует последний валидный локальный снимок, указывая его дату. Отсутствующие/закрытые тарифом метрики не заменяются нулём.

## Локальный запуск с реальными данными

После успешной загрузки JSON-файлов в `leveli/football/.cache/firebase-export` выполните из корня репозитория:

```sh
python3 leveli/football/local_server.py
```

Скрипт запустит read-only сервер только на `127.0.0.1`, откроет браузер сразу на странице футбола и напечатает ссылку вида `http://127.0.0.1:<порт>/leveli/?football-local=1#football`. Данные читаются из локальной папки. Firebase SDK не загружается и Firebase не используется. Остановить сервер можно через Ctrl+C.

Локальная ссылка доступна только на этом Mac. Экран не становится доступен на iPhone через интернет: для этого потребуются публикация снимков и отдельно настроенный авторизованный доступ, которые здесь не подключаются.

Если файлов нет, приложение покажет сообщение. Снимки старше 36 часов помечаются как устаревшие. Список сезонов при смене турнира строится только по имеющимся снимкам выбранного турнира.

Загрузчик сохраняет таблицы и матчи для PL, PD, SA, BL1, FL1, а также матчи CL. Таблицу CL и список бомбардиров бесплатный экспорт не предоставляет, поэтому приложение не показывает для них выдуманные данные.

Тесты без API/Firebase:

```sh
python3 -m unittest discover -s leveli/football/tests -v
node --test leveli/football/tests/test_ui_data.mjs
```
