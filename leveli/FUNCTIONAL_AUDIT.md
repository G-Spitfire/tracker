# Левели — согласованные требования и функциональный аудит

**Статус:** функциональный аудит завершён на 41 согласованном решении; действует последующее уточнение предметной динамики от 6 ноября 2026 года (см. раздел в конце файла), которое заменяет прежние правила №14, №20 и №21 в части метода сравнения; последующие уточнения — только при обнаружении действительно значимой неопределённости. Технические интервалы повторного чтения Firebase согласовывать не требуется. Расхождения кода и план внедрения: [IMPLEMENTATION_AUDIT.md](IMPLEMENTATION_AUDIT.md).  
**Дата начала аудита:** 2026-11-05.  
**Область:** только самостоятельное приложение `leveli/`. **WordScene не относится к этому документу.**

> Этот файл описывает **принятые решения**, а не утверждает, что они реализованы. При разработке сверять с кодом, тестами, реальными данными Firebase и загрузчиком на Mac. Пока аудит не закончен, **не менять поведение приложения автоматически**.

## Ранее утверждённая структура главной

1. Сиреневый яркий дизайн (вариант 1). Приветствие: «Привет!»; после входа имя **только из профиля Firebase**.
2. «Как у меня дела?» — круговая диаграмма количества предметов с прогнозом/итогом 5, 4, 3, 2 и категорией без прогноза; в центре общий средний балл. Нажатие на сектор фильтрует список предметов.
3. «Моя успеваемость» — график накопительного среднего в течение **текущей четверти**, календарная ось на всю четверть, без выдуманных будущих точек.
4. «Мои ориентиры» — слева «Молодец», справа «Подтянуть», по умолчанию до 3 предметов в колонке.
5. «Все предметы» — полный кликабельный список.
6. Выбор исторической четверти — в настройках, а не на главной.

## Функциональный аудит — закрытые вопросы

| № | Вопрос | Принятое решение |
|---|---|---|
| 1 | Вход | **A:** один раз войти в Firebase; сохранять действующую сессию, не требовать пароль при каждом открытии. |
| 2 | Загрузка/устаревание данных | Сохранённые оценки показывать сразу. Не выводить сообщение «Нет сети» ребёнку. Маленькая подпись с датой актуальности оценок и отдельным цветовым индикатором успешности синхронизации. |
| 3 | Повтор при сбое | **Б:** если Mac не смог синхронизировать дневник, повторять каждые **30 минут** до успеха или следующего планового запуска. |
| 4 | Когда красный индикатор | **Б:** не после первого неудачного запуска, а после неудачи первой повторной попытки (через 30 минут); время последнего успеха остаётся видимым. |
| 5 | Официальный итог vs прогноз | **A:** официальная четвертная оценка заменяет прогноз в диаграмме; предмет учитывается один раз. |
| 6 | Минимум оценок для прогноза | **Б:** прогноз показывать при **3+ текущих оценках**; при 0–2 «Мало оценок». Официальный итог показывается независимо от числа оценок. |
| 7 | Общий средний | **A:** среднее **по предметам**, в расчёт входят предметы с хотя бы одной текущей оценкой; каждый предмет имеет равный вес. |
| 8 | Порог четвертного прогноза | **A:** сохранить пороги из `school-model.js`: 4.60→5, 3.60→4, 2.60→3, ниже→2. |
| 9 | Веса оценок | **C:** если дневник передаёт официальные веса, учитывать их; иначе веса равны 1. Не вводить свои коэффициенты. |
| 10 | Частично отсутствующие веса | **A:** отсутствующий вес каждой оценки считать равным 1; официальные веса остальных применять. |
| 11 | Оценка задним числом | **A:** относить к дате школьной работы, а не дате выгрузки; накопительная история может пересчитаться. |
| 12 | Смысл графика | **A:** на дату рассчитывать накопительный общий средний **как среднее предметных средних**, с учётом весов, от начала четверти. Последняя точка должна согласовываться с центральным значением при одинаковом составе данных. |
| 13 | Интерактивность графика | **A:** график **не кликабелен**, без всплывающих подсказок; допускается компактное изменение относительно начала четверти. |
| 14 | «Молодец» и «Подтянуть» | **C:** «Молодец» — прогноз 5 без ухудшения; «Подтянуть» — прогноз 2–3 **или** ухудшение последних трёх оценок относительно общего предметного среднего минимум на 0.50. Предмет только в одной группе; приоритет у «Подтянуть». |
| 15 | Уже выставлен итог | **Б:** предмет с официальной четвертной оценкой **исключать из обоих ориентиров** (но оставлять в диаграмме и полном списке). |
| 16 | Порядок ориентиров | **Б:** «Подтянуть»: сначала прогноз 2, затем 3, затем ухудшение при прогнозе 4/5; внутри групп — средний балл по возрастанию. «Молодец»: самый высокий средний первым. Максимум 3 изначально. |
| 17 | Если в ориентире больше трёх | **Б:** ссылка «Показать все (N)» раскрывает остальных на главной; «Свернуть» возвращает три. Нажатие на предмет открывает его детали. |
| 18 | Порядок общего списка | **A:** по русскому алфавиту; при фильтрации по сектору круговой диаграммы порядок сохраняется. |
| 19 | Состав строки предмета | **В:** подробная строка — **название, средний балл, прогноз/официальный итог, число оценок, динамика последних оценок и цветовой индикатор**. Нажатие открывает предмет. |
| 20 | Основа определения динамики предмета | **A:** сохраняем сравнение **среднего последних трёх текущих оценок** со **средним за всю текущую четверть по этому предмету** (а не с тремя предыдущими оценками). Действующее значимое ухудшение — последние три ниже среднего по предмету минимум на **0,50**. Правило положительной/нейтральной визуальной динамики будет согласовано отдельно. |
| 21 | Визуальный индикатор динамики в строке предмета | **A:** три состояния относительно среднего за текущую четверть (решение №20): последние три оценки выше среднего минимум на **+0,50** — зелёная стрелка вверх; ниже минимум на **−0,50** — красная стрелка вниз; изменение между −0,50 и +0,50 — нейтральный индикатор. При менее чем трёх текущих оценках динамику не показывать. Значение разницы можно показывать рядом со стрелкой. |
| 22 | Содержимое экрана предмета | **Б:** показывать средний балл, прогноз/официальный итог, динамику, график и историю оценок, а также **цель**: ориентировочно сколько будущих пятёрок подряд необходимо, чтобы достичь следующего порога прогнозируемой четвертной оценки, с учётом уже известных официальных весов. Расчёт будущих оценок пока **не утверждён**: нужно отдельно согласовать их предполагаемый вес, формулировку, ограничения и случаи недоступности цели. Не выдавать математический сценарий за гарантию школьного итога. |
| 23 | Вес будущих оценок при расчёте цели | **А:** все гипотетические будущие пятёрки считать с **весом 1**. Уже полученные оценки учитывать по официальным весам (если указаны), иначе по весу 1 (решения №9–10). В интерфейсе пояснять предположение: «Если следующие оценки будут пятёрками с обычным весом». Число пятёрок — математический сценарий, а не гарантированный школьный результат. |
| 24 | Слишком большое число пятёрок для улучшения прогноза | **Б:** если расчётная цель составляет **1–10 пятёрок** с весом 1, показывать точное минимальное количество; если требуется **11 или больше**, точное число ребёнку не показывать, вместо него выводить: «Для следующей оценки потребуется значительное улучшение результатов». При этом текущий средний балл и прогноз всегда остаются видимыми, вычисления не изменяются. |
| 25 | Состояние цели при прогнозе 5 | **Б:** если по предмету **ещё не выставлена официальная четвертная оценка**, но прогноз уже **5**, вместо расчёта будущих пятёрок показывать положительное сообщение: «Отличный результат! Сейчас прогноз — 5. Продолжай в том же духе». Не рассчитывать «запас прочности» на плохие оценки. |
| 26 | Блок цели после выставления официальной четвертной оценки | **Б:** вместо расчётной цели показывать лаконичное сообщение «Четвертная оценка выставлена — N», где N — фактическая официальная оценка. Не показывать количество будущих пятёрок и не сравнивать официальный результат с прогнозом в блоке цели. Средний балл, историю и график предмета сохранять. |
| 27 | Блок цели при недостатке оценок для прогноза | **Б:** если нет официальной четвертной оценки и текущих оценок менее трёх, вместо прогноза и расчёта будущих пятёрок показывать, сколько оценок ещё нужно до минимального порога: при 0 — «Для прогноза нужны 3 оценки», при 1 — «Для прогноза нужно ещё 2 оценки», при 2 — «Для прогноза нужна ещё 1 оценка». После третьей текущей оценки рассчитывать прогноз и применять правила цели №22–26. Уже полученные оценки и их средний балл остаются доступными. |
| 28 | История оценок по предмету | **Б:** показывать **дату школьной работы, числовую оценку, тип работы (если передан дневником), официальный вес (если передан дневником)**. Сортировать от более поздних дат к более ранним; не придумывать недостающие поля. Не группировать по неделям. Информация о весе не должна подменяться предположением «1», если вес не передан: вес 1 используется только внутри расчёта по №10. |
| 29 | Отображение официальной четвертной оценки в деталях предмета | **Б:** показывать официальный четвертной итог **отдельно в верхней части экрана предмета**; в хронологической истории оставлять только текущие оценки, участвующие в расчёте среднего балла. Официальный итог не дублировать в истории и не учитывать в среднем. Другие типы итогов (годовые, полугодовые) не подменяют четвертной результат. |
| 30 | Фильтрация истории оценок | **Б:** два режима — **«Все»** (по умолчанию, вся история текущих оценок) и **«Контрольные»** (контрольные, проверочные и самостоятельные работы). Фильтрация действует только на список истории, не влияет на расчёт среднего, прогноз или график. Тип работы определять по реальным данным дневника; оценки с неизвестным типом остаются в «Все». Официальные четвертные итоги отображаются отдельно (№29), а не попадают ни в один фильтр истории. |
| 31 | График на экране предмета — окончательное уточнение | **А (подтверждено):** один графический блок с переключателем «Средний балл / Оценки». **По умолчанию** — линейный график накопительного среднего балла по предмету с учётом официальных весов текущих оценок (№9–10); по нажатию «Оценки» — столбчатое представление отдельных текущих оценок, один столбик на каждую оценку (№32). Режимы не показывать одновременно. График строится за выбранную четверть; переключение меняет только представление, не расчёты, историю, прогноз или цель. **Конфликт с ранее выбранным вариантом C (два графика) разрешён явным уточнением пользователя в пользу А.** |
| 32 | Несколько текущих оценок за один день на столбчатом графике | **А:** каждая текущая оценка отображается **отдельным столбиком**, даже если за одну дату получено несколько оценок. Столбцы располагаются хронологически по датам школьных работ; для совпадающих дат — в стабильном порядке, при доступном времени по времени. На узком экране обеспечить горизонтальную прокрутку при большом количестве оценок, без сведения столбцов к нечитаемой ширине. Официальные четвертные итоги не включать (№29), вес не изменяет высоту столбца (№31). |
| 33 | Подробности оценок при просмотре столбчатого графика | **А (уточнение пользователя):** график — только визуализация, **без карточек и переходов при нажатии на столбец**. На столбиках показывать сами оценки, а полная расшифровка по дате, виду работы и доступному официальному весу остаётся в списке истории **ниже графика** с фильтрами «Все / Контрольные» (№28, №30). Не дублировать подробную историю внутри графика. |
| 34 | Длинная история оценок | **Б:** первоначально показывать **10 последних текущих оценок** в выбранном режиме истории («Все» либо «Контрольные»); кнопка **«Показать ещё»** добавляет следующие 10, пока список не закончится. Сортировка от новых к старым (№28); фильтр определяет набор, к которому применяется постраничное раскрытие (№30). Если осталось менее 10 — добавить остаток; при исчерпании скрыть кнопку. Официальный четвертной итог не включать в счётчик истории (№29). |
| 35 | История оценок при выборе другой четверти | **А:** история оценок, средний балл, прогноз/официальный итог, график и цель на экране предмета относятся **только к выбранной четверти**. Не добавлять оценки из других четвертей в историю, не предоставлять отдельный переключатель «Весь год» внутри истории. При смене четверти заново применить выбранный период к данным предмета и показать первые 10 строк истории в соответствии с №34. |
| 36 | Предмет без оценок в выбранной четверти | **Б:** сохранять предмет в общем списке даже при **0 текущих оценок** и отсутствии официального четвертного итога. На экране предмета показывать «Пока нет оценок за эту четверть»; вместо прогноза и цели — «Для прогноза нужны 3 оценки» (№27). График и история пустые, без подставных данных и оценок других четвертей. Если официальный итог уже есть, его показывать по приоритету №5/26 даже при нуле текущих оценок. |
| 37 | Предметы без оценок на главной | **Б:** предмет с **0 текущих оценок и без официального четвертного итога** показывать **только в полном списке предметов** с подписью «Нет оценок»; не добавлять его в круговую диаграмму и «Мои ориентиры». При наличии официального четвертного итога показывать предмет на диаграмме независимо от числа текущих оценок (№5), но не в «Моих ориентирах» (№15). Предметы с 1–2 текущими оценками не приравнивать к предметам с нулём: к ним применяется «Мало оценок» (№6). |
| 38 | Полностью пустая выбранная четверть на главной | **Б:** если в выбранной четверти **нет ни одной текущей оценки и ни одного официального четвертного итога по всем предметам**, вместо круговой диаграммы, графика и блока «Мои ориентиры» показывать единое сообщение: **«Новая четверть началась! Оценки скоро появятся»**. Ниже сохранять полный список предметов, включая предметы без оценок (№36–37). Не подмешивать результаты других четвертей. |
| 39 | Пустая прошлая четверть | **Б:** если выбрана **прошлая четверть** и по ней нет ни текущих оценок, ни официальных четвертных итогов, вместо сообщения о начале новой четверти показывать **«За выбранную четверть нет данных об оценках»**. Не делать вывод о причинах отсутствия данных, не подставлять оценки другого периода, сохранять список предметов при наличии списка из источника. Не добавлять отдельную кнопку перехода к текущей четверти в этом состоянии. |
| 40 | Данные ещё не загружены или загрузка не удалась | **Б:** пока не получены ни актуальные данные, ни доступная локальная копия — показывать **«Загружаем оценки…»**; если загрузка не удалась и сохранённой копии нет — **«Не удалось получить данные об оценках»**. Если локальная копия доступна — **сразу показывать её** с согласованным индикатором актуальности последней успешной синхронизации (№2–4), без навязчивого предупреждения «Нет сети». Состояния недоступности/загрузки не путать с действительно пустой текущей или прошлой четвертью (№38–39). |
| 41 | Повторение запроса к Firebase после ошибки без локальной копии | **В:** приложение **самостоятельно периодически повторяет запрос данных к Firebase до успешного получения**, без кнопки «Повторить» и без необходимости перезагрузить страницу. Между попытками сохраняется состояние ошибки из №40 («Не удалось получить данные об оценках») при отсутствии кэша. Повторяется только **чтение Firebase**, не Mac→дневник→Firebase синхронизация (№3–4). При наличии пригодной локальной копии она отображается сразу (№2, №40), несмотря на сетевые сбои. **Интервал и стратегия повторов пока не определены**; согласовать отдельно, не приписывать решению №41 интервал 30 минут от Mac-синхронизации. |

## Mac → электронный дневник → Firebase: найденные факты

- На пользовательском Mac найден `~/Library/LaunchAgents/local.family.spb-grade-sync.plist`.
- Файл запускает Python-скрипт `~/Library/Application Support/SpbSchoolGradesProbe/sync_then_upload.py`.
- `StartCalendarInterval`: **07:00, 14:00, 19:00 по локальному времени Mac**.
- Пользователь подтвердил: синхронизация с дневником работает только при выключенном активном VPN.
- На момент проверки `launchctl print gui/$(id -u)/local.family.spb-grade-sync` сообщил `Could not find service`: файл существует, но его регистрация и регулярное выполнение **не подтверждены**.

## Несоответствия и вопросы для реализации

1. Действующий `school-model.js` прогнозирует уже по одной оценке; решение №6 требует минимум три. Применить одинаковый порог к кругу и строкам.
2. Действующий расчёт среднего без официальных весов; решения №9–12 требуют проверить реальный формат выгрузки, затем привести к единому вычислению в центре диаграммы, графике и предметах.
3. Действующие «Сильные/Требуют внимания» сравниваются с общим средним (разница ±0.30); решения №14–17 заменяют критерий на прогноз и динамику, исключают итоговые предметы и задают новые правила сортировки/раскрытия.
4. Существующая диаграмма приоритетно использует официальный итог; необходимо удостовериться, что «за год» и другие виды итоговых не принимаются за четвертную оценку.
5. График по решению №13 не должен предлагать интерактивное управление.
6. Строка предмета по решению №19 должна показывать в том числе число оценок, динамику и цвет.
7. Пока не проверено, передаёт ли загрузчик **все предметы**, в том числе без числовых оценок. Визуализация «Мало оценок» зависит от состава выгрузки.
8. Если нет текущих оценок, но уже выставлен официальный итог: предмет участвует в круге, но не в общем среднем (№5, №7).
9. **Особый случай:** выбранная через настройки прошлая четверть и возврат к текущей; точное поведение при возвращении следует проверить при реализации.
10. **Важная неопределённость:** отсутствие поля официального веса считаем весом 1 по решению №10, но смысл отсутствия поля в школьных данных пока не подтверждён.
11. **Важная неопределённость:** календарь четвертей может зависеть от школы; зафиксировано требование текущей четверти и календарной оси, точные границы проверить.
12. Индикатор актуальности должен быть основан на **успешной синхронизации Mac ↔ дневник ↔ Firebase**, а не на успешном сетевом чтении из Firebase.
13. Решение №20 сохраняет базу сравнения последних трёх оценок со средним предмета за четверть; это **не** сравнение с предыдущими тремя. «Подтянуть» по ухудшению (№14) согласуется с этим выбором. При внедрении официальных весов (№9–10) необходимо единообразно определить, применяются ли веса и к среднему последних трёх; до проверки данных не делать произвольного различия между расчётами. Вывод «улучшилось», «без изменений» и визуальный порог положительной динамики **ещё не утверждены**.
14. Решение №21 определяет симметричные пороги индикатора (±0,50), согласованные с порогом ухудшения по №14 и сравнением по №20. При ровно ±0,50 состояние считается значимым. Важно: индикатор показывает **отклонение последних трёх оценок от среднего за четверть**, а не изменение средней оценки во времени. При внедрении весов потребуется одинаково определять средние для этих двух величин; числовая разница и цвет должны вычисляться из одной и той же модели. При официальной четвертной оценке динамику можно показывать в общем списке, но такой предмет исключён из «Моих ориентиров» (№15).

15. Решение №22 добавляет на экран предмета подсказку о цели; при этом веса будущих оценок **неизвестны заранее** (№9–10), пороги прогноза фиксированы (№8), прогноз требует не менее трёх текущих оценок (№6), а официальный четвертной итог важнее прогноза (№5). Не показывать расчёт как универсальную гарантию, если школа выставляет оценки по дополнительным правилам. Вопрос о весе будущих пятёрок **закрыт решением №23: вес 1**. Для уже выставленной четвертной оценки цель «улучшить прогноз» неприменима.

Нельзя использовать фактический средний балл вместо суммы взвешенных оценок и суммы весов при расчёте количества пятёрок. Нужно предусмотреть случаи: итог уже выставлен (цель неприменима), прогноз уже 5 (более высокого прогноза нет), недостаточно оценок для прогноза (№6), неоправданно большое требуемое число пятёрок и отсутствие данных о весах. Последующие правила отображения цели согласовываются отдельно.

17. Решение №24 ограничивает только **представление** цели, а не алгоритм прогноза и не результаты вычислений. Граничные значения: 10 — показать число, 11 — показать текст; расчёт будущих пятёрок с весом 1 сохраняется (№23). Формулировку не использовать для официально завершённого предмета (№5, №15) или при уже достигнутом прогнозе 5; состояния этих случаев согласуются отдельно. Не округлять число пятёрок вниз и не выдавать приблизительную оценку за точный расчёт.

18. Решение №25 не противоречит порогам прогноза (№8) и минимальному числу оценок (№6): приветствие о прогнозе 5 возможно при наличии **трёх или более текущих оценок**. Приоритет официального четвертного итога (№5) важнее: при уже выставленной официальной оценке (включая 5) фразу «Сейчас прогноз — 5» не показывать, поскольку это уже не прогноз. Поведение блока при официальном итоге и при 0–2 текущих оценках требует отдельного решения.

19. Решение №26 согласуется с приоритетом официальной оценки (№5), исключением завершённого предмета из ориентиров (№15) и положительным сообщением только для **прогноза** 5 (№25). При наличии официальной четвертной оценки сначала показывать факт завершения и число N, **не** подсказку про повышение прогноза; официальная оценка за год не должна ошибочно приравниваться к четвертной. Открытый особый случай: 0–2 текущие оценки и нет официальной четвертной оценки — дальнейшее поведение блока цели уточнить отдельно.

20. Решение №27 закрывает ранее открытый случай 0–2 текущих оценок (№6, №19, №22): показывать **недостающее количество**, не предварительный прогноз и не цель из будущих пятёрок. Приоритет официальной четвертной оценки остаётся выше (№5, №26) даже при 0–2 оценках; в этом случае показываем факт завершения, а не ожидание ещё одной оценки. При 0 оценок предмет должен присутствовать в исходных данных; полнота списка предметов по-прежнему требует проверки (пункт 7). Для расчёта порога учитываются только текущие, не итоговые оценки.

Решение №28 согласуется с датой школьной работы (№11), официальными весами (№9–10) и подробным экраном предмета (№22). **Важное различие:** отсутствие веса означает вес 1 для вычисления среднего, но история не должна показывать его как полученный из дневника официальный вес. При нескольких оценках за один день порядок внутри даты требует предсказуемой сортировки (при наличии времени записи — по времени, иначе стабильный порядок). Вопрос о четвертном итоге в истории **закрыт решением №29**: итог отдельно, история только текущих оценок. Фильтры истории согласованы решением №30: «Все» и «Контрольные».

При отсутствии точного времени обеспечить детерминированный порядок внутри дня. Не менять правило неинтерактивного графика главной (№13).

Это не отменяет переключение двух **режимов одного графика** (№31) и не затрагивает неинтерактивность графика главной (№13). История и график используют согласованные исходные текущие оценки; фильтр истории не влияет на столбцы и накопительный средний (№30).

Чтобы не смешивать порции разных наборов, при переключении «Все / Контрольные» (№30) возвращать видимое количество к первым 10 нового набора; это правило — техническое следствие, требующее проверки удобства при реализации. Не сокращать перечень исходных оценок для расчёта среднего, прогноза и графика: ограничение касается только видимых строк истории (№7–12, №31). При 0–10 элементах кнопка «Показать ещё» отсутствует, при 11 и более появляется.

28. Решение №35 устанавливает единый период для всех показателей предмета и согласуется с №6–12, №22, №28–34. При смене четверти не переносить из предыдущей четверти ни оценки, ни ранее выставленный официальный итог; необходимо проверить, как существующий загрузчик помечает четверти и типы итогов. Порционная история (№34) должна сбрасываться на первые 10 записей нового периода; фильтр «Все / Контрольные» остаётся независимым от выбора периода (№30). Отдельная потенциальная сложность: в исторической четверти может присутствовать официальный итог и приоритет его отображения сохраняется (№5, №26, №29).

Решение №36 согласуется с №6, №27 и №35: отсутствие текущих оценок не исключает предмет из полного списка (№18) и не разрешает показывать чужую четверть. **Зависимость от источника:** проверить, передаёт ли Mac→дневник→Firebase полный перечень учебных предметов, включая предметы без оценок; если нет, выполнить доработку источника данных, а не придумывать предметы или считать их отсутствие признаком отсутствия оценок. Не считать «нет оценок в полученном наборе» доказательством начала четверти; необходимо различать достоверно пустую четверть, отсутствие данных из-за синхронизации и выбранный прошлый период. Точный текст для прошлой четверти и ошибки данных согласовать отдельно; не заменять ими согласованную формулировку для новой четверти. При наличии хотя бы одной текущей оценки или официального четвертного итога единое пустое состояние не показывать.

Оба состояния исключают подстановку данных другого периода (№35) и сохраняют предметы (№36–37), если их список действительно доступен. **Закрыто решением №40:** при загрузке и ошибке без локальной копии показывать отдельные состояния, а при наличии копии — её с индикатором актуальности (№2–4).

33. Решение №40 согласуется с локальным кэшем и индикатором успешной синхронизации (№2–4): **если копия есть, показывать её сразу, не ждать Firebase**. Не считать ошибку чтения Firebase доказательством сбоя запланированной синхронизации Mac→дневник→Firebase; статус её последнего успеха и порог покраснения остаются отдельными. Состояния «загружаем»/«не удалось» возникают при отсутствии пригодной копии; они не подменяют честные пустые состояния №38–39 после успешного получения данных. Решением №41 выбраны автоматические повторные попытки **чтения Firebase** без ручной кнопки; они не должны запускать Mac-синхронизацию.

34. Решение №41 устраняет открытый вопрос №40 о способе повторной загрузки: при ошибке **без кэша** оставлять сообщение об ошибке, но повторять запрос Firebase автоматически до успеха. Это не противоречит №2–4: 30-минутный цикл повтора на Mac применяется только к неудачной **плановой синхронизации**, не к клиентскому чтению Firebase. Нет утверждённого интервала, лимита, backoff и поведения при уходе приложения в фон — обсудить отдельно, чтобы не создавать частые лишние запросы или бесконечные активные таймеры в неактивной вкладке. Не показывать ложное пустое состояние (№38–39) из-за ошибки чтения.

## Уточнение предметной динамики — 6 ноября 2026 года (новое действующее правило)

**Решение пользователя: вариант Б.** Для динамики по предмету сравниваются последние три текущие оценки с непосредственно предшествующими тремя текущими оценками за **ту же выбранную четверть**. Это решение отменяет сравнение последних трёх со средним за всю четверть в решениях №14, №20, №21 и связанных пояснениях выше. Сам общий средний балл и прогноз четвертной оценки по-прежнему вычисляются по всем текущим оценкам выбранной четверти.

- Сортировка — по дате школьной работы, при совпадении дат — стабильный порядок. Официальные четвертные/годовые итоги исключаются.
- Минимум **6 текущих оценок**. При 0–5 оценках динамика и стрелка отсутствуют; наличие прогноза при 3–5 оценках от этого не зависит.
- При 6+ оценках используются **последние 6**: первые 3 образуют предыдущий блок, следующие 3 — последний. В обоих блоках учитываются официальные веса оценок (если отсутствует — вычислительный вес 1). Разница = взвешенное среднее последних трёх − взвешенное среднее предыдущих трёх.
- Значение от +0,50 включительно — зелёная стрелка вверх; от −0,50 включительно — красная вниз; между порогами — нейтральный индикатор, при этом числовое изменение можно показывать. Порог и исключение предметов с официальным итогом из ориентиров сохраняются.
- Одинаковая формула применяется в блоке «Мои ориентиры», в строках «Все предметы» и на экране предмета. Распределение предметов между «Молодец» и «Подтянуть» использует новый признак ухудшения: разница ≤ −0,50. В остальных правилах приоритет прогноза 2–3 и исключение официальных итогов сохраняются.
- Интервал определяется **оценками, не днями**: при новой текущей оценке окно сдвигается на одну позицию; повторной договорённости по времени не требуется.
- Пример без весов: `4, 5, 4 | 2, 5, 5` → 4,33 и 4,00, разница −0,33, **нейтрально**; две последние пятёрки не гарантируют положительную динамику по этому алгоритму.

**Статус внедрения:** изменение спецификации; само по себе не означает, что новый метод уже реализован и опубликован в `school-model.js` или `index.html`. При реализации обновить расчёты, браузерные проверки и фиктивные тесты, не изменять реальные оценки.
